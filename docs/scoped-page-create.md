# Scoped Notion page creation (#77)

The internal `NotionClient::create_scoped_page` workflow takes an explicit Notion parent page ID, title, Markdown content, optional emoji icon and trusted server-owned `LifecycleScope`. Unknown arbitrary property maps are never accepted. It checks the canonical parent UUID, bounded title/body/icon and control/bidi spoofing, then issues a single page creation POST. Writes run no ancestry walk and no root gate (owner decision, #691): Notion's own permission check for the token decides reach.

A creation receipt must include a canonical returned page UUID, HTTPS Notion URL and the correct physical parent. Then up to three **read-only GET /pages/{id}** attempts confirm matching page, parent, URL, title and active status. Complete authoritative Markdown must exactly match the requested body before verified completion. Incorrect or missing readback fails closed. A successful but unverified/ambiguous POST is never automatically retried. The durable once-only wrapper and independent local refresh status are described in [verified writes and refresh](write-refresh.md); callers must reconcile unknown outcomes before manually retrying.

This is an internal adapter, not a public MCP write tool. It does not expand authorization, accept untrusted properties, introduce full-page overwrite. Tests use credential-free mock Notion API with verification outcomes and exhausted readback.
